# Что осталось подтвердить для M1

M0 проверена локально и в Colab. Три CPU-пробы подтвердили передачу через Drive, затем реальный Qwen3-0.6B закреплённой revision `c1899de289a04d12100db370d81485cdf75e47ca` завершил inference на Tesla T4 в float16. Обе попытки `sum_positive` прошли public 2/2 и private 2/2, последняя награда 1, статус `completed`, инфраструктурных ошибок 0. Worker остановлен после пяти завершённых запросов: probe и четырёх проверок кандидатов. Первая попытка уже правильная, поэтому recovery не подтверждён; одна задача не является оценкой качества. Подробные результаты: `docs/m1_validation.md`.

Пользователь возобновил короткие GPU-проверки 4 ноября. Следующий запуск: `RUN_TRAINING=True`, `RUN_INFERENCE=False`, `PERSIST_TRAINING=True`. При сохранённом T4 runtime можно использовать `REUSE_ENV=True` со старым `ENV_DIR` и новым `CHECKOUT_DIR`. По умолчанию модельные этапы notebook остаются выключенными. Перед обучением обязательны transport preflight и актуальный GPU doctor. Для закрытия M1 остаются:

1. Выполнить SFT/GRPO на T4, проверить реальные optimizer updates, masks/logprobs и дисперсию rewards. На маленькой CPU-модели теперь подтверждено точное равенство конечных весов, optimizer, scheduler и RNG между непрерывными двумя шагами и новым процессом 1+1. Это не GPU-валидация.
2. Проверить GPU checkpoint/resume в новом процессе и восстановление после потери Colab runtime. Сохранить adapter, optimizer, scheduler, RNG и результаты проверки состояния.
3. Отдельно проверить recovery на эпизоде с ошибочной первой попыткой. Успех текущего `sum_positive` не демонстрирует исправление по feedback.
4. Перед расширением обучения оценить задержки и устойчивость Drive на соответствующей нагрузке. Три CPU-пробы и один inference не доказывают надёжность транспорта или пригодность для training.
5. Использовать только явно просмотренный KodCode-пилот: прежние семь execution-valid задач содержали примеры из условия в private tests и противоречия спецификации. Структурная/исполнительная проверка не заменяет ручную. См. [аудит данных](data_audit_20261104.md). Массовая обработка и финальный аудит датасета остаются последующими этапами.

Целевой RL backend пользователя остаётся verl + vLLM. Проверен контракт Agent Loop и метаданные конкретных версий; текущий Python 3.13.16 несовместим с выбранным verl 0.9.1, поэтому перенос требует отдельного Python 3.12 окружения. Не смешивать этот стек с уже установленным TRL. Подробный [план и границы spike](backend_decision.md).

До настоящего обучения отдельно проверить, что hidden feedback не влияет на prompt, stopping или выбор кандидата, а инфраструктурные сбои не получают reward=0. Проверки M0 останутся регрессионными тестами протокола, но не заменят preflight нового backend.

Версии ML-стека закреплены и проверены на маленькой CPU-модели. Docker preflight и небольшой KodCode-пилот выполнены локально. Успешный T4 inference не заменяет GPU training/resume и исследовательскую оценку качества. Публикация данных, длительное обучение и платные сервисы не входят в текущую итерацию.

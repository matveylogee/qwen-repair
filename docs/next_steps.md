# Что осталось подтвердить для M1

M0 проверена локально и в Colab. Первый удалённый CPU probe Colab → Drive → Mac Docker прошёл 2/2 теста: round trip 42,7218 с, executor 1,1225 с. Это один измеренный round trip; два завершённых запроса в Mac worker не дают второго измерения задержки. Worker остановлен. Следующий шаг: три коротких CPU-повторения для оценки разброса задержки, затем отдельный T4 inference. Обучение остаётся выключенным до отдельного включения. Настройка Drive: `docs/m1.md`; фактические результаты: `docs/m1_validation.md`.

1. Для повторных проверок выбрать один опубликованный commit для Mac и Colab и новое одинаковое `SESSION_NAME`. Запустить один Mac `queue-worker` с папкой `My Drive/qwen-repair-exchange/sessions/<SESSION_NAME>`.
2. Подготовить CPU runtime через `notebooks/01_m1_feasibility.ipynb`: полный `COMMIT_SHA`, имя сессии, базовая установка, CPU doctor и Drive mount. Оставить `RUN_INFERENCE=False` и `RUN_TRAINING=False`; при повторной установке использовать новые каталоги checkout и окружения.
3. Выполнить `executor-preflight`, затем три последовательных `executor-probe` с отдельными путями `--output`. Сравнить round-trip latency и время executor, сохранить отчёты, остановить worker и оценить нагрузку Drive. При ошибках или неприемлемой задержке продолжить диагностику связи.
4. После оценки повторных измерений провести отдельный запуск на T4 с `RUN_INFERENCE=True` и `RUN_TRAINING=False`, снова подготовив worker и проверив транспорт. Сохранить GPU doctor: GPU, VRAM, Python, torch/CUDA и версии. Выполнить inference закреплённой `Qwen/Qwen3-0.6B` на авторских fixtures; проверить `environment.json`, точные token IDs и отдельную private evaluation.
5. Обучение оставить выключенным до отдельного включения `RUN_TRAINING`. Тогда выполнить SFT/GRPO smoke: первый процесс сохраняет checkpoint после шага 1, второй продолжает до шага 2. Проверить итоговый `global_step`, adapter round-trip, masks/logprobs и отчёт о дисперсии rewards. Успешный inference не заменяет проверки обучения.
6. Скачать полный ZIP с отчётами и checkpoints до завершения runtime, затем остановить worker. Сопоставить VRAM, скорость генерации, время эпизодов и executor с результатами CPU-проверок. При необходимости сохранить завершённый архив в Drive.
7. При успешном коротком цикле отдельно оценить inference на уже проверенном KodCode-пилоте. Для этого перенести весь validated bundle и запустить worker с соответствующим registry. Массовая обработка и финальный аудит датасета пока не нужны.

До настоящего обучения отдельно проверить, что hidden feedback не влияет на prompt, stopping или выбор кандидата, а инфраструктурные сбои не получают reward=0. Проверки M0 останутся регрессионными тестами протокола, но не заменят preflight нового backend.

Версии ML-стека закреплены и проверены на маленькой CPU-модели. Docker preflight и небольшой KodCode-пилот выполнены локально. Один успешный удалённый probe не заменяет повторные измерения задержки, T4 preflight и реальный rollout Qwen. Публикация данных, длительное обучение и платные сервисы не входят в текущую итерацию.

# Что осталось подтвердить для M1

M0 проверена локально и в Colab. Код M1 реализован, локальный Docker и интеграция trainer проверены. После переподключения Drive локальная проверка нагрузки и файловой очереди прошла. Полный M1 ещё требует запуска Qwen и обучения на T4, а также измерения удалённого транспорта. HTTP остаётся альтернативой, notebook пока настроен на HTTP. Настройка Drive: `docs/m1.md`; фактические результаты: `docs/m1_validation.md`.

1. Адаптировать `notebooks/01_m1_feasibility.ipynb` для Drive mount и `configs/colab_queue.yaml`. Для новой сессии можно выбрать отдельную подпапку обмена, указав один и тот же относительный путь на Mac и в Colab.
2. Выбрать один опубликованный commit для Mac и Colab, затем T4, заполнить `COMMIT_SHA` и выполнить установку. Сохранить результат `doctor --gpu`: GPU, VRAM, Python, torch/CUDA и проверку закреплённых зависимостей.
3. Запустить один `queue-worker` на Mac с папкой `My Drive/qwen-repair-exchange`. Выполнить `executor-preflight` и `executor-probe` из Colab с файловым профилем. Подтвердить настоящий запрос к Mac и измерить round-trip latency до загрузки модели. При неприемлемой задержке остановиться на проверке связи.
4. Выполнить inference закреплённой `Qwen/Qwen3-0.6B` на авторских fixtures. Проверить `environment.json`, траектории с настоящими token IDs и отдельную private evaluation. Tokenizer, non-thinking template и контроллер уже реализованы; сейчас проверяется их работа на T4 с удалённым executor.
5. Выполнить SFT и GRPO smoke-команды из notebook: первый процесс сохраняет checkpoint после шага 1, второй продолжает до шага 2. Проверить итоговый `global_step`, adapter round-trip, masks/logprobs и отчёт о дисперсии rewards. Успешный inference не заменяет проверки обучения.
6. Скачать полный ZIP с отчётами и checkpoints до завершения runtime, затем остановить worker. Сопоставить VRAM, скорость генерации, время эпизодов и executor с результатами CPU-проверок. При необходимости сохранить завершённый архив в Drive.
7. При успешном коротком цикле отдельно оценить inference на уже проверенном KodCode-пилоте. Для этого перенести весь validated bundle и запустить worker с соответствующим registry. Массовая обработка и финальный аудит датасета пока не нужны.

До настоящего обучения отдельно проверить, что hidden feedback не влияет на prompt, stopping или выбор кандидата, а инфраструктурные сбои не получают reward=0. Проверки M0 останутся регрессионными тестами протокола, но не заменят preflight нового backend.

Версии ML-стека закреплены и проверены на маленькой CPU-модели. Docker preflight и небольшой KodCode-пилот выполнены локально. Эти проверки не заменяют T4 preflight, реальный rollout Qwen и измерение связи с Colab. Публикация данных, длительное обучение и платные сервисы не входят в текущую итерацию.

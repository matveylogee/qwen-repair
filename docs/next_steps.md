# Что осталось подтвердить для M1

M0 проверена локально и в Colab. Три повторных CPU probe Colab → Drive → Mac Docker прошли: round trip 45,62384 / 58,76414 / 47,67209 с, среднее 50,68669 с, медиана 47,67209 с; Docker 2,55959 / 0,71420 / 0,73210 с. Commit `0026f49` и 45 хешей исходных файлов совпали на Mac и в Colab, identity и checksums всех трёх запросов и ответов проверены. За 163,2 с наблюдения Drive показал средние 11,912% CPU и максимум 15,652% в 34 интервалах. Worker автоматически завершился с кодом 0 после трёх ответов и периода ожидания перед выходом. Эти три пробы не доказывают надёжность транспорта или его пригодность для обучения. Настройка: `docs/m1.md`; подробные результаты: `docs/m1_validation.md`.

1. Для отдельной T4-проверки выбрать один опубликованный commit с профилем `configs/m1_infer_t4_smoke.yaml` для Mac и Colab и новое одинаковое `SESSION_NAME`. Запустить один Mac `queue-worker` с папкой `My Drive/qwen-repair-exchange/sessions/<SESSION_NAME>`.
2. Открыть `notebooks/01_m1_feasibility.ipynb` в T4 runtime: задать полный `COMMIT_SHA`, имя сессии, `INFERENCE_CONFIG="configs/m1_infer_t4_smoke.yaml"`, `RUN_INFERENCE=True`, `RUN_TRAINING=False`. Значения обоих флагов по умолчанию остаются `False`; при повторной установке использовать новые каталоги checkout и окружения.
3. Выполнить установку, Drive mount, executor preflight/probe и GPU doctor. Сохранить GPU, VRAM, Python, torch/CUDA и версии. При ошибках остановиться до загрузки весов.
4. Выполнить inference закреплённой `Qwen/Qwen3-0.6B`: одна авторская задача `sum_positive`, две попытки, `float16`, не более 512 новых токенов на попытку. Проверить `environment.json`, точные token IDs и отдельную private evaluation. Это проверка исполнения на T4, без обучения.
5. Обучение оставить выключенным до отдельного включения `RUN_TRAINING`. Тогда выполнить SFT/GRPO smoke: первый процесс сохраняет checkpoint после шага 1, второй продолжает до шага 2. Проверить итоговый `global_step`, adapter round-trip, masks/logprobs и отчёт о дисперсии rewards. Успешный inference не заменяет проверки обучения.
6. Скачать полный ZIP с отчётами и checkpoints до завершения runtime, затем остановить worker. Сопоставить VRAM, скорость генерации, время эпизодов и executor с результатами CPU-проверок. При необходимости сохранить завершённый архив в Drive.
7. При успешном коротком цикле отдельно оценить inference на уже проверенном KodCode-пилоте. Для этого перенести весь validated bundle и запустить worker с соответствующим registry. Массовая обработка и финальный аудит датасета пока не нужны.

До настоящего обучения отдельно проверить, что hidden feedback не влияет на prompt, stopping или выбор кандидата, а инфраструктурные сбои не получают reward=0. Проверки M0 останутся регрессионными тестами протокола, но не заменят preflight нового backend.

Версии ML-стека закреплены и проверены на маленькой CPU-модели. Docker preflight и небольшой KodCode-пилот выполнены локально. Успешные CPU-пробы не заменяют T4 preflight и реальный rollout Qwen. Публикация данных, длительное обучение и платные сервисы не входят в текущую итерацию.

## Исправления и воспроизводимый отбор

`load_pilot` теперь проверяет содержимое execution evidence: четыре успешных reference results, реальные verdict, число cases, провалы выбранной мутации на обоих bundles и связь candidate hash. Проверяются существование, visibility и entry point bundles, уникальные задачи и независимость входов public/private. Новые отчёты дополнительно связывают evidence с хешами reference и bundles, сохраняют код подготовки/валидации и executor preflight. Контрольные суммы обнаруживают изменение артефактов, но не являются независимым доказательством подлинности отчёта.

Статический экстрактор учитывает эквивалентные позиционные/именованные вызовы и значения аргументов по умолчанию. Повтор входа с противоречивым expected отклоняется; mutable defaults reference отклоняются как зависимость между вызовами. Подготовка проверяет source revision/row count и уникальные source IDs, сохраняет исходные metadata и row hash.

После Docker-проверки добавлен отдельный отказ для повторного keyword argument (`solve(x=1, x=2)`): AST допускает такое дерево, но превращать его в обычный словарь нельзя. В проверенных 100 source tests такого случая нет. Сохранённый validation относится к точному snapshot `validated-pipeline-source.py` до этой дополнительной проверки; старые execution hashes не переписывались.

`review_pilot` принимает явные решения для всех source IDs подготовленного набора, создаёт `review.json` и `excluded_source_ids`, сохраняет статус `pending_execution_validation`. Он не угадывает примеры в естественном языке и не запускает код. CLI не расширялся.

Артефакты этого аудита: `runs/data-audit-20261104-afc67a90e575/`. `audit.json` содержит инвентаризацию и хеши старых файлов; `review-decisions.json` содержит все десять решений. Подкаталоги `prepared-final` и `reviewed-final` созданы заново, старые sealed bundles не перезаписывались. Повторить отбор в новом каталоге можно так:

```python
import json
from pathlib import Path
from qwen_repair.data.pilot import prepare_pilot, review_pilot

audit = Path("runs/data-audit-20261104-afc67a90e575")
replay = Path("runs/data-audit-replay")  # Должен быть новым каталогом.
prepare_pilot(Path("data/kodcode-source"), replay / "prepared", max_tasks=10)
review_pilot(
    replay / "prepared", replay / "reviewed",
    decisions=json.loads((audit / "review-decisions.json").read_text()),
    review_id="manual-m1-data-audit-20261104",
)
```

Точная команда изолированной проверки нового поднабора:

```bash
.venv/bin/python -m qwen_repair pilot-validate \
  --source runs/data-audit-20261104-afc67a90e575/reviewed-final \
  --output runs/data-audit-20261104-afc67a90e575/validated \
  --executor-config configs/docker_local.yaml
```

Команда завершилась с кодом `0`. Новый `validated` содержит две задачи (`Filter_41148_I`, `Filter_57093_I`) и четыре bundles. Все восемь запусков reference прошли, всего 46 case executions. Из десяти запусков мутаций четыре дали `failed`, два `passed`, четыре `timeout`; выбранная мутация каждой задачи дала именно `failed` на обоих bundles. Таймауты относятся к другим проверенным мутациям, инфраструктурных ошибок не было. Сумма длительностей executor results составила 44,772 с; это не полное время команды.

`execution-summary.json` сохраняет итог, а `validated-pipeline-source.py` содержит точный исходник использованного pipeline. Его SHA256 совпадает с `validation_code_sha256` в manifest: `1b87ef896352d99c448c7e0309f6f35d12c72e58b6f98554ebf00b54099dbfe4`. Хеши прежних sealed артефактов после проверки не изменились. Целевой набор проверок `tests/test_pilot.py` прошёл: 26 tests.

Код reference, исходных тестов и кандидатов на хосте не исполнялся. AST и literal values анализировались статически; реальные вызовы разрешены только Docker executor после preflight. Папки Google Drive в этом аудите не сканировались и не изменялись.

## Границы пилота

Две выбранные задачи относятся к одному семейству бинарного поиска и остаются в train. Они не дают независимого held-out сравнения или разнообразия для обучения. Группировка пока использует нормализованный AST и точное условие; глобальные near-duplicates, родственные задачи и pretraining-контаминация не исключены. Финальные 80/10/10 группы не сформированы. Разделение случаев выполнено до выбора мутации, но полнота тестов относительно всего входного домена не доказана.

Следующий ограниченный этап данных: независимо просмотреть эти две пары и результаты Docker; затем расширять аудит в пределах уже локальных 100 строк, например ещё на 10 кандидатов, сохраняя причины исключения. Короткие M1 training-прогоны разрешены; для расширения за пределы авторских fixtures нужен разнообразный проверенный набор. Для M2 остаются аудит 50–100 примеров, группировка полного корпуса до split и заморозка held-out.

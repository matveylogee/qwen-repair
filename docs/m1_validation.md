# Проверки M1

Проверки 29 октября и 4 ноября 2026. Полный GPU feasibility ещё не завершён. Ниже разделены фактически выполненные проверки и работа, для которой нужен Colab T4.

Suite 29 октября: **124 passed** за 38,95 с, включая настоящий Docker, закреплённый tokenizer и tiny CPU training/resume. TRL выдал ожидаемое предупреждение об экспериментальном `rollout_func`; API закреплён и проверен. `pip check` в обоих окружениях не обнаружил конфликтов. Wheel собран и установлен отдельно от checkout: все 38 исходных файлов и fixtures совпали побайтно, CLI help и M0 demo/summarize прошли.

Данные не публиковались; кандидаты исполнялись только в Docker.

Первый длительный запуск worker в Drive обнаружил ошибку: сбой чтения существующего ответа приводил к попытке записать другой payload поверх неизменяемого файла. Исправленный worker сохраняет точный ответ для повторной публикации и не выполняет запрос заново при частичном или повреждённом ответе. Отдельные regression tests покрывают эти случаи, перезапуск и ограничение кэша. Старые heartbeat теперь отбрасываются по timestamp в имени до чтения содержимого; актуальность проверяется после I/O. Для этого формата обе стороны должны использовать новый commit.

Загрузчик Parquet дополнительно проверен повторным чтением 100 строк: процесс завершился с кодом 0, данные побайтно совпали с первоначальным срезом, SHA256 `5e05383ab17b94ae81e5db8523961230a1651eb9bb8dfdf9be85695ac863d39f`. Фоновое prefetch отключено, reader и файл закрываются явно.

Исходник установленного TRL 1.16.0 совпадает с [тегом v1.16.0](https://github.com/huggingface/trl/blob/v1.16.0/trl/trainer/grpo_trainer.py): SHA256 `1c3dc2253fb3653269c11dfce4f946f74201a4cb63e0887a37e8e3bb4a3f5503`. `rollout_func` остаётся экспериментальным API, поэтому версия закреплена и проверяется перед обучением.

Историческая заметка: 4 ноября был проверен экспериментальный HTTP/Cloudflare transport; локальные проверки прошли, удалённое соединение не заработало. Этот код, конфигурации и инструкции удалены; подробные отчёты прежней версии оставлены только в игнорируемом `runs/` и не подтверждают возможности текущего пакета.

Проверки после удаления фиксируются отдельно.

## Notebook с файловой очередью и удаление экспериментального транспорта

Из пакета удалены сервер, клиент, авторизация и конфигурация экспериментального HTTP-транспорта. Notebook использует Drive и отдельную папку `sessions/<SESSION_NAME>`. По умолчанию он устанавливает базовый пакет и выполняет только CPU doctor, executor preflight/probe и скачивание отчётов. Модельные этапы и GPU-зависимости доступны только при явном включении `RUN_INFERENCE` или `RUN_TRAINING`, после успешной проверки транспорта.

Исправлена гонка отмены в файловом worker: задержавшееся чтение маркера не отменяет следующий запрос, а принятая отмена повторяется до завершения текущего исполнения. Регрессионные тесты проверяют обе ситуации.

Полный локальный запуск `.venv-ml/bin/python -m pytest -q --tb=short` с pinned Docker image и существующим кешем tokenizer завершился: **155 passed, 1 warning** за 39,15 с, без пропусков. Предупреждение TRL относится к experimental `rollout_func`. В набор входят настоящий Docker, маленькие CPU-интеграции trainer и проверки управления ячейками notebook с подменёнными внешними вызовами. Последние подтверждают отключение GPU/обучения по умолчанию, но не выполняют Colab.

`qrepair doctor`, M0 `demo` и `summarize` завершились с кодом 0. Wheel собран через изолированную PEP 517-сборку; 38 файлов пакета совпадают с исходниками, удалённых HTTP-модулей внутри нет. SHA256 wheel: `da12aa22fe288074a425a2a1b12e6893826105e74a7419604dc9bf26985de002`. Первоначальная сборка без build isolation не выполнялась из-за отсутствующего setuptools в CPU virtualenv; обычная изолированная сборка прошла. Отчёт: `runs/m1-drive-notebook-a97fc39c9f784064bc2e28f73b5f2377/validation.json`.

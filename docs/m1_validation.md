# Проверки M1

Проверки 29 октября и 4 ноября 2026. Полный GPU feasibility ещё не завершён. Ниже разделены фактически выполненные проверки и работа, для которой нужен Colab T4.

## Аудит перед возобновлением GPU training, 4 ноября

Пользователь снял паузу с коротких SFT/GRPO-проверок. Новый GPU training/resume пока не выполнен. Исправления и локальная проверка:

- Кандидат с `os._exit(125/126/127/137)` раньше мог быть ошибочно классифицирован по коду Docker CLI. Теперь проверяется состояние контейнера: ошибка кандидата не исключается из знаменателя как `infra_error`, OOM определяется отдельно. Реальный Docker preflight, авторский fixture и четыре варианта exit прошли интеграционную проверку.
- Прерывание файлового запроса во время публикации или ожидания теперь публикует cancellation. Проверены случаи прерывания непосредственно после записи запроса.
- Resume отвергает каталог другого run, несовпадающий step и уже завершённый план. Сегменты сохраняют отдельные отчёты, PID и хост; callback фиксирует actual/skipped optimizer calls, конечные веса и ненулевые градиенты. Нулевая дисперсия rewards не выдаётся за обучающий сигнал.
- Маленькие CPU SFT и GRPO после нового процесса 1+1 дали те же конечные adapter tensors, optimizer, scheduler и Python/NumPy/torch RNG, что непрерывные два шага. У sampled GRPO совпали completion token streams. В отдельном тесте с контролируемыми действиями/rewards подтверждены ненулевые градиенты действий обеих попыток и нулевые градиенты feedback. Эти проверки не подтверждают CUDA или реальный FP16 scaler.
- Добавлены `training-export`, `training-import`, `training-audit`. Проверены полный checksum inventory, сохранение предыдущей копии, отсутствие десериализации checkpoint objects, отказ на повреждённом/частичном архиве, traversal и превышении размера. Notebook возобновляет новый процесс из checkpoint, прочитанного из persistent-копии. Настоящая потеря Colab runtime ещё не проверена.
- При аудите KodCode прежний execution-valid набор из семи задач признан непригодным для скрытой оценки без пересмотра: часть private-примеров видна в prompt, есть противоречия условиям. Подготовлен просмотренный train-only subset; [подробный аудит](data_audit_20261104.md).
- По исходникам/метаданным проверен кандидат verl 0.9.1 + vLLM 0.24.0. Он требует отдельного Python/ML-окружения; GPU-интеграции пока нет. [Решение по backend](backend_decision.md).

Итог основной команды `.venv/bin/python -m pytest -q --tb=short`: **212 passed, 3 skipped**, 6,51 с. Пропуски относятся к optional tiny ML, Docker и tokenizer; они дополнительно проверены отдельными командами: 6 ML CPU-тестов, реальный Docker integration и локальный pinned tokenizer. В ML был ожидаемый warning об экспериментальном `rollout_func`. CPU doctor, demo и summarize завершились с кодом 0, артефакты `runs/m1-hardening-72ee04b9db/`. `git diff --check` прошёл.

Suite 29 октября: **124 passed** за 38,95 с, включая настоящий Docker, закреплённый tokenizer и tiny CPU training/resume. TRL выдал ожидаемое предупреждение об экспериментальном `rollout_func`; API закреплён и проверен. `pip check` в обоих окружениях не обнаружил конфликтов. Wheel собран и установлен отдельно от checkout: все 38 исходных файлов и fixtures совпали побайтно, CLI help и M0 demo/summarize прошли.

## Исправление создания окружения Colab

Первый запуск notebook в Colab с Python 3.13 остановился на `python -m venv` с кодом 1, до подключения Drive. Полного вывода subprocess не было, поэтому причина этого сбоя не установлена. Notebook теперь создаёт окружение через `venv --without-pip`, а системный pip устанавливает CPU- и GPU-пакеты в целевое окружение через `--python`. Ошибки этих команд выводятся в ячейку. При повторной попытке используются новые пути, существующие каталоги сохраняются.

В одноразовом контейнере с закреплённым образом Python 3.13.18 намеренно отключён `ensurepip`: обычный `venv` завершился с кодом 1, новый способ создал окружение и установил базовый пакет. Импорты и установленная CLI-команда прошли; проверена изоляция окружения. Отчёт: `runs/colab-bootstrap-py313-7af1e8c4/report.json`. Это воспроизведение возможной причины и проверка способа установки в Linux, а не установление причины исходного сбоя или успешный запуск Colab.

После исправления CPU-набор тестов: **151 passed, 3 skipped** за 5,27 с; пропущены необязательные ML-интеграции, Docker preflight и tokenizer без соответствующих параметров окружения. В числе пройденных тестов 16 проверок notebook/CLI, включая вывод ошибки установки и остановку дальнейших этапов. `qrepair doctor`, M0 `demo` и `summarize` завершились с кодом 0; отчёты: `runs/m1-colab-bootstrap-d2fc6c8d144d/`. Обучение в этой проверке не выполнялось.

# Архитектура M0

Пакет `qwen_repair` отделяет историю модели от скрытой оценки. В этой итерации он работает на CPU с четырьмя собственными fixtures. Сеть и GPU для demo не используются.

```text
TaskRecord -> PromptView -> EpisodeController -> ScriptedPolicy
                                |
                                v
                         parser + FakeExecutor (public)
                                |
                                v
                           Trajectory
                                |
                                v
                  отдельная скрытая оценка (fake)
                                |
                                v
                       PrivateEvaluation -> metrics
```

## Граница данных

`TaskRecord` содержит ссылки на public/private test bundles и reference. `PromptView` создаётся через явный список разрешённых полей: условие, сигнатура, buggy code и публичные идентификаторы. Полный `TaskRecord.model_dump()` не используется для prompt.

Контроллер получает публичный bundle ID. Он не получает скрытых результатов, reference code или hidden cases. `PrivateEvaluation` вычисляется после завершения эпизода и сохраняется в отдельном JSONL. Эти данные не участвуют в истории, выборе следующего действия или условии остановки.

Схемы событий имеют `schema_version`; JSONL сохраняет связи через `run_id`, `episode_id` и `task_id`. Синтетические результаты явно маркируются. Поля сверх схемы отклоняются, чтобы случайное расширение prompt не прошло незамеченным.

## Протокол

`ScriptedPolicy` получает сообщения и настройки генерации и возвращает очередной заранее подготовленный ответ. Парсер принимает ровно один Markdown-блок `python`, проверяет AST, имя и сигнатуру точки входа. Он не выполняет код. Ошибка формата расходует попытку и возвращается как публичная диагностика без вызова executor.

`FakeExecutor` сопоставляет bundle ID и хеш кандидата с заданным `TestResult`. Неизвестная комбинация означает ошибку инфраструктуры. Ни строки из fixture, ни код ответа не передаются в `exec`, импорт или subprocess. Fake verdict не является результатом реального запуска тестов.

По умолчанию контроллер делает две попытки, в том числе после публичного успеха. История второй попытки содержит предыдущий ответ и ограниченный публичный feedback. Formatter ограничивает длину и очищает абсолютные пути и внутренние traceback-строки. Ошибка инфраструктуры останавливает эпизод с отдельным статусом.

Бюджеты M0 измеряются байтами UTF-8. Это воспроизводимый счётчик для scripted backend. При подключении Qwen его нужно заменить реальным токенизатором и chat template. Переполнение контекста фиксируется явно; условие и код не сокращаются молча.

## Оценка и воспроизводимость

Скрытая оценка относится к каждому кандидату, но терминальную награду определяет только последний. Невалидная попытка не наследует успех предыдущей. Инфраструктурная ошибка исключает эпизод из обычного знаменателя с явной причиной; отсутствие результата не превращается в ошибку решения.

`summarize` читает траектории и скрытую оценку, соединяет их по ID и вычисляет метрики. Он не разбирает stdout кандидата. Cumulative success хранится отдельно от final success. Синтетические сценарии не образуют исследовательскую выборку для сравнения моделей.

Manifest сохраняет параметры, seed и сведения о коде и среде; контрольные суммы позволяют проверять артефакты. Время и ID запуска могут различаться между повторами. Логика M0 находится в пакете; notebook содержит только установку и вызовы CLI.

## Расширения M1

`TransformersPolicy` использует закреплённые модель и tokenizer, non-thinking chat template и настоящий счётчик токенов. `TokenConversation` хранит исходные prompt/completion token IDs: при следующей попытке feedback добавляется к существующему префиксу. M0 сохраняет отдельный счётчик байтов.

`DockerExecutor` запускает JSON-функцию в ограниченном контейнере, а сравнение с ожидаемым ответом выполняет доверенный supervisor. Код кандидата исполняется только в Docker на Mac; ожидаемые результаты остаются у supervisor.

`FileQueueExecutor` передаёт запросы из Colab локальному Docker worker через синхронизируемую папку Google Drive с payload/checksum/READY и проверкой IDs, хешей, сроков и отмены. Каждая сессия использует `qwen-repair-exchange/sessions/<SESSION_NAME>`; имя сессии должно совпадать на Mac и в Colab. Worker получает тесты из доверенного registry, опрашивает очередь раз в секунду и публикует heartbeat раз в 30 секунд. Успешные preflight и probe обязательны до загрузки модели; отсутствие Docker или worker не включает выполнение кандидатов на хосте.

Notebook по умолчанию устанавливает CPU-пакет, подключает Drive и вызывает CLI для проверки транспорта. Inference и training включаются отдельными параметрами; только тогда устанавливается extra `gpu` и выполняется GPU doctor. Модельная и обучающая логика остаётся в пакете.

Inference сохраняет обычный run bundle с `synthetic_demo=false`. SFT и GRPO сохраняют training manifest, masks/rollouts, отдельную private evaluation и checkpoints с completion marker. SFT использует стандартный Transformers Trainer; GRPO использует стандартный TRL trainer с проверенным `env_mask`. Обучение ограничено smoke-профилем; большие эксперименты пока не запускаются.

## Ограничения

M0 не исполняет недоверенный код. Локальные проверки M1 подтверждают ограниченный Docker-протокол и интеграцию trainer на маленькой CPU-модели; для полного feasibility нужны отдельные T4 и Colab-to-Mac прогоны. Fake-интерфейсы не дают гарантий изоляции. Глобальная дедупликация датасета, финальные research splits и оценка качества относятся к следующим этапам.

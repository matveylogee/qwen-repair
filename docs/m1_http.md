# HTTP executor между Colab и Mac

Для следующей проверки M1 выбран HTTP transport: Qwen и trainer работают в Colab, а Mac принимает запросы и исполняет кандидатов в Docker. Локальный сервер слушает только `127.0.0.1:8765`; временный HTTPS-адрес Cloudflare направляет к нему запросы Colab.

Это изменение первоначального плана, который обходился без публичного туннеля. После паузы из-за нагрузки Drive Desktop добавлен альтернативный транспорт для сравнения задержек. Причина нагрузки Desktop до конца не установлена; файловая очередь остаётся поддерживаемым вариантом. Drive можно использовать для хранения завершённых архивов. Фактические измерения и границы выполненных проверок перечислены в [m1_validation.md](m1_validation.md); работа HTTP-туннеля с Colab и T4 ещё требует отдельного запуска.

## Mac: сервер

Используйте на Mac и в Colab один commit с HTTP backend. Подготовка Docker и проверка pinned image описаны в [m1.md](m1.md). Из корня проекта запустите сервер:

```bash
source .venv/bin/activate
qrepair http-worker --config configs/docker_local.yaml --port 8765 --token-file runs/m1-http-token.txt
```

Команда создаёт файл токена с правами `0600`, если его ещё нет, и использует существующий при повторном запуске. Токен не выводится в терминал. Сервер требует успешного Docker preflight, использует фиксированные лимиты и доверенный registry. Оставьте этот терминал работающим.

## Mac: временный HTTPS-адрес

Если `cloudflared` ещё не установлен, официальный способ для macOS использует Homebrew:

```bash
brew install cloudflared
```

Альтернативные официальные сборки доступны на [странице загрузок Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/).

Следующий шаг открывает временный внешний адрес локального executor. Запускайте его перед проверкой связи с Colab, во втором терминале:

```bash
cloudflared tunnel --url http://127.0.0.1:8765 --no-autoupdate --loglevel info
```

Скопируйте выведенный адрес `https://…trycloudflare.com` в параметр `EXECUTOR_URL` notebook. Quick Tunnel предназначен для разработки, не требует собственного домена или Cloudflare-аккаунта, меняет адрес при новом запуске и не гарантирует uptime. Адрес прекращает работать после остановки процесса. [Документация Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

Обработчик требует bearer token. Любой, у кого есть URL и токен, может отправлять код на выполнение в Docker с установленными лимитами и registry. Держите URL и токен приватными; Cloudflare является посредником HTTPS-соединения. Не добавляйте `--allowed-mail`: его интерактивная проверка email несовместима с CLI-клиентом. [Ограничения Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations)

Для передачи токена в скрытое поле Colab скопируйте его без вывода в терминал:

```bash
pbcopy < runs/m1-http-token.txt
```

Не вставляйте токен в ячейку кода, YAML, URL, чат или Git. `runs/` исключён из Git, но файл токена также не следует включать в архив результатов.

## Colab: проверка до загрузки весов

Откройте `notebooks/01_m1_feasibility.ipynb`, выберите T4 и заполните:

- `COMMIT_SHA`: полный SHA опубликованного commit с HTTP backend.
- `EXECUTOR_URL`: текущий HTTPS-адрес туннеля без пути, query-параметров и токена.

Notebook устанавливает `.[gpu]` в отдельный virtualenv и выполняет `doctor --gpu`. Затем скрытое поле `getpass` записывает токен в `QREPAIR_EXECUTOR_TOKEN` текущего процесса. CLI-подпроцессы наследуют его через окружение; значение не попадает в аргументы команд, конфигурацию или сохранённые outputs.

Notebook создаёт `executor.yaml` из `configs/colab_http.yaml`, подставляет endpoint и вызывает `executor-preflight`, затем `executor-probe`. Шаблон содержит пустой endpoint и требует заполнения перед самостоятельным CLI-запуском. В YAML сохраняются только endpoint, имя переменной токена, digest и лимиты.

Первый preflight проверяет готовность сервера и совместимость настроек. Probe выполняет реальную авторскую задачу и записывает время всего запроса отдельно от времени executor. До успешного probe не переходите к inference или обучению. Ошибка авторизации, недоступный туннель или сбой Docker должны исправляться до загрузки Qwen.

Далее notebook запускает inference и короткие SFT/GRPO проверки с resume. Он сохраняет конфигурации и результаты локально в Colab. При перезапуске туннеля обновите `EXECUTOR_URL` и повторите preflight/probe; существующие отчёты требуют новых имён или нового каталога запуска.

## Завершение

Скачайте ZIP из последней ячейки. В архив входит endpoint из конфигурации, но значение токена туда не записывается. После проверки остановите `cloudflared` и `http-worker` через `Ctrl+C` в обоих терминалах. Последняя ячейка удаляет `QREPAIR_EXECUTOR_TOKEN` из окружения notebook; при повторном запуске проверки введите токен снова.

Перед передачей архива другим людям остановите туннель. Эти инструкции описывают временный стенд для feasibility.

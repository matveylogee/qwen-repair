# Qwen Code Repair

M0 проверяет протокол исправления Python-кода на CPU: подготовленный ответ, публичная обратная связь, следующая попытка, отдельная скрытая оценка и сохранение артефактов. `ScriptedPolicy` возвращает заданные строки, а `FakeExecutor` ищет заранее записанный результат. Код кандидатов и тестовые случаи не исполняются.

Все результаты demo отмечены `synthetic_demo: true`. Они проверяют работу харнесса и формулы метрик; качество Qwen по ним оценивать нельзя. В M0 нет скачивания модели, обучения или настоящего изолированного исполнителя.

## Установка

Нужен Python 3.11 или новее. Команды выполняются из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
qrepair --help
```

Если `.venv` уже создан, достаточно активировать его и установить пакет. Основные зависимости: Pydantic для схем и PyYAML для конфигурации; `dev` добавляет pytest. CUDA, torch, Docker и внешние аккаунты для M0 не нужны.

## Локальный запуск

```bash
qrepair doctor --config configs/local_demo.yaml
qrepair demo --config configs/local_demo.yaml --output runs/demo
qrepair summarize --run runs/demo
python -m pytest -q
```

`doctor` показывает версию Python и пакета, конфигурацию, наличие Docker и метаданные необязательных GPU-библиотек. Он не проверяет работоспособность GPU или изоляции и не выгружает переменные окружения.

`demo` требует новый каталог вывода, чтобы не затереть предыдущий запуск. Для повторной проверки используйте другой путь, например `--output runs/demo-repeat`. Повтор с тем же seed воспроизводит сценарии и существенные события; `run_id` и время меняются.

Конфигурация по умолчанию задаёт две попытки и пять сценариев: исправление после ошибки, неверный формат, повторную ошибку, сбой инфраструктуры и регрессию после успешной попытки. Публичный успех не завершает эпизод досрочно. Невалидный последний ответ остаётся последней попыткой и не заменяется предыдущим решением.

Для проверки лимита `max_attempts` разрешены значения от 1 до 3; третья попытка повторяет последний подготовленный ответ. `seed` записывается в manifest и ID эпизодов. Scripted policy не использует случайную генерацию.

В M0 длины измеряются числом байтов UTF-8, включая служебное оформление сообщений. Это явный счётчик для синтетического режима, а не токенизатор Qwen. Лимиты `max_new_tokens`, `max_context_tokens` и `max_feedback_tokens` применяются к этому счётчику. При переполнении контекста эпизод останавливается с отдельной причиной; исходная задача не обрезается.

## Артефакты

Каждый каталог запуска содержит:

- `manifest.json`: ID запуска, версии, seed, конфигурацию и сведения о воспроизводимости.
- `config.yaml`: разрешённую конфигурацию запуска.
- `trajectories.jsonl`: попытки, сообщения, публичные результаты и причины остановки.
- `private_evaluation.jsonl`: скрытые результаты и терминальную награду отдельно от истории модели.
- `metrics.json`: агрегаты из структурированных событий.
- `environment.json`: сведения о среде без секретов.
- `checksums.json`: контрольные суммы артефактов.

`summarize` повторно читает сохранённые события и вычисляет те же метрики. `final_success_rate` зависит от последней попытки. `solved_by_attempt` учитывает любой успех среди первых попыток и не является стандартным pass@k. `recovery_rate` измеряет исправление после первой ошибки, `regression_rate` измеряет потерю первого успешного решения. Сбой инфраструктуры даёт отсутствующую награду и отдельный счётчик исключённых эпизодов, а не нулевую награду модели.

Четыре собственные мини-задачи находятся в `src/qwen_repair/data/fixtures/` и включаются в устанавливаемый пакет. Это тестовые данные M0; они не импортированы из KodCode.

## Colab и следующий этап

Откройте `notebooks/00_preflight.ipynb`, укажите свой URL репозитория и полный commit SHA. Notebook устанавливает эту версию пакета и вызывает `doctor`, fake demo и `summarize`. Выводы ячеек в репозитории не сохранены. Для этого notebook достаточно CPU runtime.

M1 требует отдельного задания: выбрать GPU runtime, проверить настоящий executor, подключить Qwen и выполнить короткие SFT/GRPO проверки с сохранением и восстановлением. GPU runtime сам по себе не даёт проверенной изоляции для исполнения кандидатов.
